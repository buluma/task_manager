# HTTP API

The task, project, priority, agent and notification routes need `Authorization: Bearer <token>` when `GR8R_TOKEN` is set. `/api/rev` and `/api/state` stay open for the browser app, so bind the server to a private interface (see [server.md](server.md)).

| Request                                                          | Does                                                                                                                                                                                                                                            |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/tasks?status=&priority=&project=&cycle=&q=&archived=1` | list tasks (`cycle` is `current`, `none` or a date)                                                                                                                                                                                             |
| `POST /api/tasks`                                                | create a task: `title` plus optional `project`, `status`, `priority`, `due`, `start`, `cycle`, `labels`, `desc`, `estimate`, `assignee`, `completed`, `recur`                                                                                   |
| `GET /api/tasks/GR-1`                                            | one task by key                                                                                                                                                                                                                                 |
| `PATCH /api/tasks/GR-1`                                          | change `title`, `desc`, `status`, `priority`, `due`, `start`, `labels`, `assignee`, `cycle`, `estimate`, `completed` (a completion date, for done tasks only), `recur` or `project` (moving re-keys the task from the target project's counter) |
| `DELETE /api/tasks/GR-1`                                         | archive the task (restore it from the Archive page); with `?purge=1`, delete an already archived task for good                                                                                                                                  |
| `POST /api/tasks/GR-1/subtasks`                                  | add a subtask: `title`                                                                                                                                                                                                                          |
| `PATCH/DELETE /api/tasks/GR-1/subtasks/ID`                       | rename or complete (`done: true/false`) a subtask, or remove it                                                                                                                                                                                 |
| `GET/POST /api/tasks/GR-1/deps`                                  | list what the task waits for, or add one: `{ "on": "GR-2" }`                                                                                                                                                                                    |
| `DELETE /api/tasks/GR-1/deps/GR-2`                               | remove a dependency                                                                                                                                                                                                                             |
| `GET/POST /api/tasks/GR-1/comments`                              | list a task's comments, or add one: `text` and an optional `at` (ISO date) to backdate it                                                                                                                                                       |
| `DELETE /api/tasks/GR-1/comments/ID`                             | delete one comment                                                                                                                                                                                                                              |
| `GET /api/projects?archived=1`                                   | list projects (archived ones only with the flag)                                                                                                                                                                                                |
| `POST /api/projects`                                             | create a project: `name` plus optional `key`, `desc`, `color`, `icon`, `status`, `due`, `lead`                                                                                                                                                  |
| `GET/PATCH /api/projects/GR`                                     | one project; change `name`, `desc`, `color`, `icon`, `status`, `due`, `lead`, `archived` (the key never changes)                                                                                                                                |
| `DELETE /api/projects/GR`                                        | archive the project, keeping its tasks (`PATCH` `archived: false` restores it); with `?purge=1`, delete an already archived project with its tasks, comments, files and activity for good                                                       |
| `GET /api/priorities`                                            | the priority scale, highest weight first, with how many tasks use each level                                                                                                                                                                    |
| `POST /api/priorities`                                           | add a level: `name`, `w` (1-99) and optionally `id`                                                                                                                                                                                             |
| `PATCH /api/priorities/high`                                     | rename or reweight a level (`none` always weighs 0)                                                                                                                                                                                             |
| `DELETE /api/priorities/high?replace=medium`                     | remove a level; its tasks move to `replace` (default `none`)                                                                                                                                                                                    |
| `GET/POST /api/agents`                                           | list agents, or register one (`name`); send `X-Gr8r-Agent: <name or id>` on a write to log it to that agent (attribution, not authentication)                                                                                                   |
| `GET/POST /api/notifications`                                    | list Inbox items (`?unread=1`), or raise one: `text`, optional `task` key, `snippet`, `type`; agent writes also raise some on their own                                                                                                         |
| `PATCH /api/notifications/ID`                                    | mark one read or unread: `read` (true or false)                                                                                                                                                                                                 |
| `GET/PUT /api/state`                                             | the whole workspace, guarded by a revision number (`baseRev`)                                                                                                                                                                                   |

The priority scale lives in the workspace state, so levels added through the API show up in the app's pickers, filters and grouping within a few seconds. Edit the scale in the app under Settings → Priorities, or through the API. The `urgent` level keeps its special icon and the other levels spread over one to three bars by rank.

Task `desc` is plain text by default (HTML-escaped; blank lines start paragraphs). Send `descFormat: "markdown"` with it (`--markdown` in the CLI) to render headings, lists, bold, italic, code, links and quotes; input is always escaped first, so raw HTML never gets through.

Completing a repeating task (`recur`: Daily, Weekly, Every 2 weeks or Monthly) that has a due date schedules the next occurrence, as in the app; the response carries it as `next`.
