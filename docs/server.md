# Personal server

The app works on its own from browser storage. To keep one copy of your data across browsers and devices, run the sync server, which also serves the built app and a small task API. Set `GR8R_TOKEN` to require a token on the task, project, priority, agent and notification APIs; `/api/state` and the app pages stay open, so bind it to a private interface such as your Tailscale address and never to 0.0.0.0.

```bash
npm run build
GR8R_HOST=$(tailscale ip -4) npm start     # http://<tailnet-ip>:8787, data in ~/.gr8r/state.json
```

`GR8R_HOST` (default 127.0.0.1; one address or a comma-separated list, e.g. the Tailscale IP and 127.0.0.1 when `tailscale serve` puts HTTPS in front), `GR8R_PORT` (default 8787) and `GR8R_DATA` (state file) configure it, and `GR8R_TOKEN` makes the task, project, priority, agent and notification APIs require `Authorization: Bearer <token>` (the CLI sends `GR8R_TOKEN` from its own environment). Instead of exporting variables you can put them in a `.env` file at the repo root, which is gitignored and read by both the server and the CLI; variables already set in the shell win, and `GR8R_ENV_FILE` points to a different file. `GR8R_GITHUB_TOKEN` (optional) is a GitHub token the server uses to look up the state of linked PRs for the app's PR icons. Use a fine-grained token with read-only Pull requests access to the repos you link. Without it, PRs in private repos stay uncoloured, and GitHub allows only 60 lookups an hour. If GitHub refuses the server (a bad or revoked token, 401; forbidden or rate limited, 403/429; its own errors, 5xx) or can't be reached, the server logs it to `server.err.log` and raises one Inbox item for the outage, and logs `GitHub is answering again` when it recovers. Every 10 minutes the server also looks at the 50 most recently updated PRs in each project's GitHub repo (the project's `repo`). It links each PR that names a task of that project, by its key in the PR's title or branch or after a word like "implements" or "fixes" in its body, with a `PR: URL` comment. When such a PR opens (or merges without ever having been seen open), its open tasks move to Review; when one closes without merging, the task stays put. Each raises an Inbox item. The state each PR was in at the last look is kept per repo in `pr-seen.json` beside the data file, and the first look at a repo only links, so old PRs move nothing. These links, moves and Inbox items, and the merge check's below, are made by a GitHub agent (`agent-github`, registered the first time it is needed), so the activity log tells them from yours. It then moves each task in Review whose linked PR (the newest `PR:` comment) has merged to Done, and raises an Inbox item naming the PR; tasks in other statuses are left alone, and a task put back in Review by hand stays there until the server restarts. The token does not cover `/api/rev` and `/api/state`, which the browser app uses without credentials, so it stops casual API use but not a deliberate write of the whole state; keep the server on a private interface. Open the app once so it saves its starting state, then the API accepts writes. Open tabs pick up changes made through the API within a few seconds.

The HTTP routes are listed in [api.md](api.md).

The command-line client is documented in [cli.md](cli.md).
